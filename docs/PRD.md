# SmartService-Agent 产品需求文档（PRD）

> 版本：1.0 · 2026-09 · 配套代码库：SmartService-Agent

## 1. 项目背景

以「多 Agent 智能客服平台」为载体，完整走一遍商用项目从原型到生产的全过程：
Python 原型验证 → Java 工程化 → 多 Agent 协作 → 生产级交付（认证、限流、监控、CI/CD、容器化）。
目标用户是**想系统掌握商用项目完整流程的开发者**：不仅看到功能，更能看到每个环节的工程化决策。

## 2. 目标用户与使用场景

| 角色 | 场景 |
|---|---|
| 终端用户 | 通过网页向客服提问：天气、数学计算、产品价格、退货流程、故障排查、闲聊 |
| 运营人员 | 登录管理后台查看平台健康、运营指标、会话记录，管理异常会话 |
| 开发者（学习者） | 阅读代码与文档，理解分层架构、安全、测试、监控、CI/CD 各环节 |

## 3. 用户故事

1. 作为用户，我想通过网页输入问题并实时看到流式回答，以便获得即时反馈。
2. 作为用户，我想自由地聊任何话题（通用 AI 助手），天气/计算场景自动使用工具。
3. （已下线）作为用户，我询问退货时可以按状态机逐步走流程，以便知道每一步该做什么。
4. 作为运营人员，我想一眼看到平台 / Redis / LLM 三层健康状态，以便及时发现故障。
5. 作为运营人员，我想看到请求量、延迟、会话数、意图分布等指标，以便评估平台运行情况。
6. 作为运营人员，我可以删除异常会话，以便管控数据。
7. 作为开发者，我希望每次提交都经过自动化测试 + 代码规范检查，以便保证质量。

## 5. 非功能需求

| 类别 | 指标 |
|---|---|
| 性能 | FAQ 直查 P95 < 300ms；LLM 路径流式首字 < 2s（依赖本地 LM Studio） |
| 安全 | 密码 BCrypt 单向；JWT 过期 24h；限流防刷；监控端口不暴露公网；审计留痕 |
| 可用性 | LLM 挂时自动降级 FAQ 直查；Redis 挂时快速失败（不拖垮线程池） |
| 可维护性 | 分层架构清晰；Checkstyle 门禁；35 测试回归；多环境配置 |
| 可观测性 | 业务日志 + 审计日志 + 健康探针 + Prometheus 指标 + 4 条告警 |

## 6. 验收标准

1. 启动服务后：聊天端流式回答、管理后台登录后可看全量指标，均可运行。
2. `mvn verify` 全绿：35 测试 + Checkstyle + Jacoco 报告生成。
3. `scripts/smoke-test.sh` 端到端通过（注册→对话→SSE→管理→健康）。
4. `scripts/health-check.sh` 退出码分级正确（0/1/2/3）。
5. 审计日志记录登录/注册/删除会话等操作。
6. CI 流水线在 GitHub 上可跑通（待推送后验证）。
