### 4.2 CI 首次运行：全红 → 定位 → 修复 → 跑绿

| 阶段 | 情况 |
|---|---|
| 首次 push 后 | 15 个 run（含 Dependabot 14 个 PR）**全部解析失败** |
| 根因 | `${{ github.repository_owner \| lower }}` —— **GitHub Actions 表达式不支持 `\| lower` 管道语法**（那是 Jinja2 写法），报 `Unexpected symbol: '|'` |
| 修复 | bash 转小写写入 `GITHUB_ENV`：`echo "OWNER_LC=${GITHUB_REPOSITORY_OWNER,,}" >> "$GITHUB_ENV"`，tags 改用 `${{ env.OWNER_LC }}`（提交 `ac0caed`） |
| 结果 | 最新 push ✅ 通过；Dependabot 依赖更新 PR 在 base 修复后**自动重跑通过**（如 `docker/build-push-action 6→7` 的 PR #17 ✅） |

### 4.3 自动化体系已生效

## 五、板块三：协作知识体系（今日系统教学）

| 主题 | 核心结论 |
|---|---|
| Docker | 镜像/容器/Dockerfile/compose 四概念；本项目 3 个部署文件已交付，缺 Docker Desktop 实测 |
| Git 提交 | 提交是本地快照（`E:\SmartService-Agent\.git\`），push 才上云 |
| PAT/token | 2021 年起 GitHub 禁用密码；PAT 最小权限 + 90 天过期 + wincred 免密 |
| 分支创建 | 分支=指针；pull **不会**建分支；`checkout -b` 是唯一创建方式 |
| 谁能建分支 | collaborator 可建可推 feature（ruleset 只锁 main）；路人只能 fork |
| 合作流程 | pull → checkout -b → 改 → push feature → 开 PR → **CI 绿 + owner 批准** → 服务器合并 → 双方 pull |
| 网页权限 | 路人网页编辑被强制 fork + PR；owner/collaborator 直接改，但 main 受 ruleset 约束 |

2. **bat 文件用纯 ASCII**：cmd 默认 GBK，UTF-8 bat 中文乱码。bat 只负责调 ps1，中文提示全在 ps1。

### 8.2 SSE 流式前端 bug 修复（22:50）✅

**用户反馈**：聊天 UI 显示用户消息 + 黄色"意图路由 → WEATHER"标签，但 AI 回复气泡完全空白。

**四步诊断**：
| 探测 | 结果 |
|---|---|
| 1. `actuator/health` 9090 | UP（llm/redis/ping 全 UP） |
| 2. curl LM Studio `/v1/chat/completions` | HTTP 200 / 0.5s（引擎正常） |
| 3. curl `/api/agent/chat` 普通端点 | 完整返回"北京今天天气晴朗..." 9.2s ✅ |
| 4. curl `/api/agent/chat/stream` SSE | 12 个 token + done 事件完美推送 ✅ |

**结论**：后端 100% 正常，问题在前端 JS 解析 SSE。

**根因**：`static/js/app.js` 第 117 行三元表达式短路求值 bug：
```javascript
const token = payload && typeof payload === 'object'
 ? '' : (payload !== null ? String(data) : '');
```
后端推 `data:北京` 时：`JSON.parse("北京")` 抛错 → `payload = null` → 三元第一项 `null && ...` falsy → 走 else 分支 → 第二项 `payload !== null` 是 false → 返回 **`''`**。所有 token 全过滤成空串。done 事件（payload 是对象）走第一个分支正常处理 → 完美吻合"标签显示但回复空白"现象。

**修复**：改清晰的条件分支——done 事件 / `payload !== null` 忽略 / `payload === null` 拼接 data。

**部署流程**（Spring Boot jar 模式必经步骤）：
1. `Stop-Process` 旧 java（jar 被进程锁，需先停才能打包）
2. `mvn -B -ntp package -DskipTests` 重新打包（6.8s）
3. `unzip -p` 验证 jar 内的修复代码（`BOOT-INF/classes/static/js/app.js`）
4. 重新 `java -jar` 启动

**两条关键教训**：
1. **Spring Boot jar 模式改前端 ≠ 即时生效**：静态资源打包进 jar（`BOOT-INF/classes/static/`），必须重新打包 + 重启进程。与 ComfyUI / Node.js 热加载完全不同。
2. **PowerShell tool 的 `Start-Process` 子进程会被回收**：非交互式 ps 进程结束会带走子 java → 几秒后死。用 Bash 工具 `run_in_background=true` 启动 java 更稳（bash 容器长期持有）。

**用户验证步骤**：浏览器 Ctrl+Shift+R 强制刷新（避开静态资源缓存），发送"北京今天天气怎么样"应看到打字机逐字渲染完整句子。
