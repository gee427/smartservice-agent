## 四、板块二：GitHub 上线全记录

### 4.1 仓库建立与推送
- 新建公开仓库 `github.com/gee427/smartservice-agent`（不勾 README/.gitignore/license）
- 配置 remote origin → 生成 PAT（`repo` + `workflow` 权限）→ 一次性推送
- **PAT 写入 wincred（Windows 凭据库）→ 此后 `git push` 完全免密**（实测通过）

### 4.2 CI 首次运行：全红 → 定位 → 修复 → 跑绿

| 阶段 | 情况 |
|---|---|
| 首次 push 后 | 15 个 run（含 Dependabot 14 个 PR）**全部解析失败** |
| 根因 | `${{ github.repository_owner \| lower }}` —— **GitHub Actions 表达式不支持 `\| lower` 管道语法**（那是 Jinja2 写法），报 `Unexpected symbol: '|'` |
| 修复 | bash 转小写写入 `GITHUB_ENV`：`echo "OWNER_LC=${GITHUB_REPOSITORY_OWNER,,}" >> "$GITHUB_ENV"`，tags 改用 `${{ env.OWNER_LC }}`（提交 `ac0caed`） |
| 结果 | 最新 push ✅ 通过；Dependabot 依赖更新 PR 在 base 修复后**自动重跑通过**（如 `docker/build-push-action 6→7` 的 PR #17 ✅） |

### 4.3 自动化体系已生效
- 🤖 **Dependabot**：自动创建 14 个依赖更新 PR（spring-boot 4.1.1 / spring-ai-bom 2.0.1 / checkstyle 3.6.0 / actions 大版本 4→7 等）
- 🛡️ **Ruleset 分支保护**（`protect-main`）：Enforcement=Active、Bypass 留空（**连 owner 也约束**）、Target=默认分支、要求 PR + status checks + 1 approval + 禁强推/禁删

## 五、板块三：协作知识体系（今日系统教学）

| 主题 | 核心结论 |
|---|---|
| Docker | 镜像/容器/Dockerfile/compose 四概念；本项目 3 个部署文件已交付，缺 Docker Desktop 实测 |
| Git 提交 | 提交是本地快照（`E:\SmartService-Agent\.git\`），push 才上云 |
| PAT/token | 2021 年起 GitHub 禁用密码；PAT 最小权限 + 90 天过期 + wincred 免密 |
| 分支创建 | 分支=指针；pull **不会**建分支；`checkout -b` 是唯一创建方式 |
| 谁能建分支 | collaborator 可建可推 feature（ruleset 只锁 main）；路人只能 fork |
| 合作流程 | pull → checkout -b → 改 → push feature → 开 PR → **CI 绿 + owner 批准** → 服务器合并 → 双方 pull |
| 网页权限 | 路人网页编辑被强制 fork + PR；owner/collaborator 直接改，但 main 受 ruleset 约束 |

## 六、今日踩坑记录（重要教训）

| # | 坑 | 教训 |
|---|---|---|
| 1 | spring-ai 的 `api-key` 是自动配置硬性要求 | 拆配置时务必保留公共层默认值，否则 test 环境 18 个测试 Context 失败 |
| 2 | Checkstyle LineLength 必须放 Checker 级 | Checkstyle 10.x 的模块层级要求 |
| 3 | `${maven.multiModuleProjectDirectory}` 单模块解析错位 | 改用 `${project.basedir}/../config/checkstyle.xml` |
| 4 | Git Bash `/tmp` 是 MSYS 虚拟路径 | Windows 原生 python 访问需 `cygpath -w` 转换 |
| 5 | curl `-w` 输出无换行 | 压测统计需显式加 `\n`，否则 50 行粘连成 1 行 |
| 6 | GitHub Actions 不支持 `\| lower` 管道 | Actions 表达式是自成一派的语法，不是 Jinja2 |
| 7 | 8080 端口 jar 被旧进程锁定 | repackage 前必须先停占用进程 |
